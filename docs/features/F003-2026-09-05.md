# F003 - 强制解析 re 前缀正则

## 功能概述

为强制域名解析规则的 pattern 字段增加 re: 前缀，使精确匹配、通配符和正则匹配可在同一字段中表达。

## 功能描述

### 核心功能

- pattern 以 re: 开头时，将去掉前缀后按 ECMAScript 正则表达式完整匹配域名。
- pattern 以 *. 开头时，继续按现有通配符规则匹配。
- 其他 pattern 继续按现有精确域名规则匹配。
- 旧 regex 字段保持兼容。

### 功能边界

- 不改变强制解析规则按配置顺序首次命中的行为。
- 不支持在一条规则中同时配置 re: pattern 与旧 regex 字段。
- re: 后无表达式或表达式非法时，记录警告并跳过该规则。

---

## 需求背景

现有正则规则需要单独配置 regex 字段，不能与 pattern 的精确和通配符写法统一。re: 前缀提供无歧义的规则类型标记，同时避免将普通域名中的点号误判为正则通配符。

---

## 技术方案

加载配置时先检查 pattern 是否以 re: 开头。若是且 regex 字段为空，去掉前缀后复用现有正则编译和匹配逻辑；其余规则沿用现有处理。

规则识别流程：

1. pattern 以 re: 开头：使用后续表达式进行完整正则匹配。
2. pattern 以 *. 开头：使用现有后缀通配符匹配。
3. 其他 pattern：使用精确匹配。

## 配置项

    {
      "force_resolve_rules": [
        {
          "pattern": "example.com",
          "ips": ["192.168.1.100"]
        },
        {
          "pattern": "*.example.com",
          "ips": ["192.168.1.101"]
        },
        {
          "pattern": "re:^(api|www)\\.example\\.com$",
          "ips": ["192.168.1.102"]
        }
      ]
    }

旧写法仍然有效：

    {
      "regex": "^(api|www)\\.example\\.com$",
      "ips": ["192.168.1.102"]
    }

## 测试用例

- 单元测试：加载 re: 正则规则后验证匹配和不匹配的域名。
- 集成测试：查询 api.re-prefix.example.net 并验证返回配置的强制 IP。
- 异常测试：验证空 re:、re: 与旧 regex 字段冲突，以及旧 regex 字段非法时都跳过规则。

---

## 注意事项

- 正则使用完整匹配；是否添加 ^ 和 $ 由规则表达式本身决定。
- 普通精确域名不应添加 re: 前缀。
- re: 写法与 regex 字段不能同时出现。

---

## 兼容性

- 现有精确、通配符和 regex 字段规则不受影响。
- 新写法仅在 pattern 以 re: 开头时启用。
