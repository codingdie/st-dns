# F002 - ST Proxy IP 黑名单同步

**创建日期**: 2026-05-29

## 功能概述

st-dns 定时从 ST Proxy 获取 IP 黑名单，并避免继续向客户端返回这些 IP。

## 功能描述

### 核心功能

- 复用 `dns_server::schedule()` 每 5 秒通过 ST Proxy console 命令 `proxy blacklist` 同步黑名单。
- 解析 `proxy blacklist` 输出时只读取每行第一列 IP，兼容 `IP\t域名列表` 格式。
- st-dns 在内存中维护当前黑名单集合。
- 对新增黑名单 IP，基于现有反向索引 `IP -> domains` 增量清理 DNS 缓存，不全量扫描缓存。
- 在 DNS record 转换为返回结果时再次过滤黑名单 IP，兜底处理并发窗口和未清理记录。

### 功能边界

- ✅ 包含 IPv4 A 记录缓存中的黑名单 IP 清理和返回前过滤。
- ✅ 包含 ST Proxy console 调用失败时保留上一轮黑名单，避免错误清空。
- ❌ 不主动恢复已物理删除的 IP；IP 从黑名单移除后等待后续远端解析自然补回。
- ❌ 不新增配置项，跟随现有 5 秒 schedule 周期。

## 技术方案

### 核心流程

```
dns_server::schedule()
    ↓
st::command::proxy::get_blacklist_ips()
    ↓
dns_record_manager::sync_blacklist_ips()
    ↓
计算新增黑名单 IP
    ↓
通过 reverse_resolve(ip) 找到受影响域名
    ↓
只修改受影响域名的 DNS record
```

### 关键技术点

1. **增量清理**
   - 使用 `dns_record_manager` 已有的 `reverse` LevelDB 反向索引。
   - 清理复杂度与新增黑名单 IP 及其关联域名数量相关，不随全部缓存域名线性增长。

2. **返回前过滤**
   - `dns_record_manager::transform()` 和 `dns_record::transform()` 读取内存黑名单。
   - 如果缓存中仍有黑名单 IP，生成解析结果时跳过。

3. **失败策略**
   - `proxy blacklist` 调用失败时不更新内存黑名单。
   - 上一轮成功同步的黑名单继续生效。

## 注意事项

- 反向索引可能存在历史脏数据，清理时以实际 DNS record 内容为准；脏索引最多导致多读一次空记录，不影响正确性。
- 如果 ST Proxy 长时间不可用，st-dns 会继续使用最后一次成功同步的黑名单。
