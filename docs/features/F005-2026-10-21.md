# F005 - 上游回环地址过滤与异常缓存失效

**创建日期**：2026-10-21  
**状态**：👀 待审核  
**优先级**：高

## 功能概述与背景

`query.sse.com.cn` 曾从上游获得 `127.0.0.1` 并被缓存，过期后仍可能先返回旧结果再刷新。
对上游 A 记录过滤整个 IPv4 回环网段，避免客户端访问自身，并使升级前的异常缓存立即失效。

## 功能描述与技术方案

- 上游结果入库前过滤 `127.0.0.0/8`，混合响应保留正常地址；全部被过滤时移除该来源的缓存。
- 历史缓存读取、解析选择、列表、导出和统计均过滤异常地址，无需清空全部数据库。
- 被完全过滤的来源不计入可用缓存来源，沿用现有缓存未命中及缺失来源刷新机制。
- 回环地址反向查询排除仅由异常上游缓存产生的域名。
- 保留 `localhost`、`.localhost` 子域和 `st-dns-force` 强制解析来源；域名判断忽略大小写和末尾根点。
- 正常公网及内网地址、正常过期缓存的后台刷新策略不变；不扩展到 IPv6 或其他特殊网段。

## 实现位置与接口

- `src/core/dns_record_manager.cpp`：入库、历史缓存和反向索引读取过滤，公共接口不变。
- `src/test/unit/cache_management_test.cpp`：网段边界、混合响应、历史缓存、来源回退和兼容性测试。
- `src/test/integration/cache_integration_test.cpp`：通过本地 DNS 服务验证过滤及强制解析兼容性。
- OpenWrt `packages/st-dns/Makefile`：同步包功能说明，包版本字段不变。

## 配置项与使用示例

默认生效，无新增配置。上游返回 `127.0.0.1,202.122.113.77` 时，只缓存并返回 `202.122.113.77`。
确需将业务域名指向本机时，可使用已有 `force_resolve_rules` 明确配置。

## 测试用例与验证

覆盖整个网段边界、相邻正常地址、混合/全回环结果、升级前未过期及过期异常缓存、备用上游、
反向索引、localhost 和强制解析兼容性。完成构建后运行全部单元测试和集成测试。

验证结果：Debug 构建成功；`sudo -n ctest --output-on-failure -j1` 全量通过，
共 74 个 CTest 项（73 个单元测试及包含 18 个用例的集成测试），耗时 224.11 秒。
其中新增 4 个单元测试及 2 个集成用例。测试使用 sudo 是因为已有测试目录、共享内存和日志文件属于 root。

## 注意事项与相关功能

历史缓存读取时过滤，不进行全库迁移；异常来源后续刷新时覆盖或移除旧数据。
过滤全部地址不会生成伪造地址，继续使用现有无可用记录处理流程。
与 [F002 黑名单同步](F002-2026-05-29.md) 叠加生效。
