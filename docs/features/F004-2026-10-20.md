# F004 - 地区地址库异步加载防阻塞

## 功能概述与状态

同步 st-proxy 的地区地址库加载修复，防止后台下载占用查询锁，拖慢 DNS 地区筛选。

- 状态：🧪 测试中
- 优先级：高
- 负责人：codingdie
- 创建日期：2026-10-20

## 需求背景与功能边界

原实现下载时持有 `default_lock`，正常地区查询也需要同一把锁。地址库缺失且下载失败时，反复下载会阻塞前台查询。
本次同步保留地区判断、缺失数据时的既有返回行为及公开接口；修复下载锁范围、重复排队与失败重试。

## 技术方案

1. 按规范化后的国家代码记录任务占位，同步与异步入口共用去重状态。
2. 在查询锁外下载、读取和解析文件，完整数据就绪后短暂加锁发布缓存。
3. 失败或异常后清除占位，按国家退避 60 秒，使用单调时钟计算重试时间。
4. 异步任务携带生命周期及请求编号，停止时清理排队占位，防止旧任务影响重新启动。

## 实现位置与接口

- `src/common/main/utils/area_ip.{h,cpp}`：同步 st-proxy 的公共实现。
- `src/common/test/area_ip_loading_test.cpp`：同步五项并发、重试和生命周期回归测试。
- `src/common/test/unit_tests.cpp`：地区单测采用本地 CIDR 数据。
- OpenWrt 的 `packages/st-dns/Makefile`：同步包功能说明。

`load_area_ips` 和 `async_load_area_ips` 的签名不变。同步入口遇到加载中或退避中的地区返回未就绪，不等待后台网络请求。

## 配置与使用示例

无需新增配置；已有地区规则继续使用，例如上游的 `"areas": ["CN"]`。
当 CN 地址库正在加载时，其他已知地区仍可查询；同一地区的新请求不再重复提交下载。

## 测试与验证

- 慢下载期间查询可返回，同步及异步重复请求只下载一次。
- HTTP 失败后按国家退避，到期后恢复加载；其他国家可独立加载。
- 下载异常清理状态；排队中及下载中的任务停止后均可重新加载。
- Debug 构建通过；新增五项回归测试全部通过。
- 全量串行执行 `sudo -n ctest --test-dir build --output-on-failure -j1`：70 项 CTest 条目中 55 项通过，14 项旧单测及集成测试组在配置加载阶段因 `SIGPIPE` 退出。
- GDB 定位到 `http::get → httplib → SSL_connect → BIO_write`，请求为 GitHub 的 CN 地址库。使用本次未修改的 `utils/http.h` 编译独立最小程序，同样以信号 13 退出，确认该失败独立于加载锁改动。
- 全量验证尚未通过，状态保留为测试中；尚未部署。

## 注意事项与相关功能

退避不修复失效下载源本身，仍需保证地址库来源可用。此次不调整国家代码配置、DNS 黑名单策略或软件包版本。
公共模块与 st-proxy 保持一致；关联 [F001 核心功能](F001-2026-02-15.md)。
